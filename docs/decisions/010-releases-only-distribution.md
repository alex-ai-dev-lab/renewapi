# ADR-010：统一检查与 Releases 离线镜像分发

状态：已接受。日期：2026-09-23。

## 背景

用户要求修复主分支失败的浏览器检查、清理旧 Releases 和 Actions 历史，
并明确要求 GHCR 历史镜像一并清理，之后所有构建仅发布到 Releases。
原工作流允许浏览器检查失败后继续发布 GHCR 镜像，主分支也没有自动创建
Release，不能满足本次要求。

## 决策

- `build-release.yml` 是唯一构建发布入口，保留主分支、产品标签和手动触发。
- 后端与双前端检查、四版本数据库验证和两组实际浏览器检查全部是镜像构建
  的前置条件。子工作流通过 `workflow_call` 复用，不再独立触发或重复写提交状态。
- 在各自原生架构的 runner 构建 amd64、arm64 镜像，验证源码标签和迁移后
  导出 Docker 归档；不登录或推送任何镜像仓库，不授予发布流程 Packages 权限。
- 归档附带镜像元数据、部署配置、QA 证据和 SHA256 校验和。先上传草稿，
  再下载并核验全部附件，成功后公开。已公开 Release 的重跑仅验证原附件。
- 源码构建创建 `renewapi-build-<sha>-<run>` 预发行标签；产品版本和标签语义
  保持不变。任何已存在标签必须解析到实际源码 SHA，不得移动或覆盖。
- Compose 只使用已经 `docker load` 导入的本地镜像，禁止自动拉取。发布附件
  中的 `default.env.example` 固定该次镜像标签，已有安装保留原配置与数据。
- Docker 归档不携带 OCI registry 证明；镜像元数据和离线校验和单独保留，
  不声称这些文件具备签名证明能力。

## 历史清理

本次用户明确授权删除旧 Releases 及附件、旧 Actions 运行和旧 GHCR 镜像。
先保存清单和失败证据，确认替代 Release 可以下载与校验，再按清单清理。
GHCR 维护使用独立分支的一次性工作流，清理前比对清单摘要，避免删除并发
新增镜像；该工作流不进入主线。原有 Git tags、用户修改和服务器容器保持原样。

## 替代范围

替代 ADR-003 中 GHCR 发布及仅手动创建源码 Release 的规则，并补充
ADR-001 中历史 Release 在用户明确授权下可清理的例外。版本独立性、
产品标签命名和 Git 历史不变性继续有效。
