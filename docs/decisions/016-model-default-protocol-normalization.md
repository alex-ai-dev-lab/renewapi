# ADR-016：依模型默认端点执行三种文本协议互转

状态：已接受。日期：2026-10-08。

用户要求 Chat Completions、Responses、Messages 三种入口相互兼容，上游默认使用已配置的模型端点，返回格式继续遵循客户端入口。已有全局端点表、渠道开关与兼容启发式分散，支持列表可能保留客户端路径而跳过默认端点；旧中转还会丢失混合文字、并行开关及重试状态。

## 决策

- 在现有 `ModelEndpointDefaults` 增加 `normalize_text_endpoints`。旧值缺省为 false，保持旧配置行为；此次上线对已核对的生产规则明确启用。无业务表或数据库结构迁移，不覆盖模型规则。
- 沿用精确匹配优先、最长前缀次之。三种文本入口使用模型默认端点；图像生成、音频、embeddings、视频和 compact 等专用接口保持独立语义。
- 通用 OpenAI/Anthropic 聚合渠道按目标协议选择适配器并保留 Base URL；原生供应商保留其鉴权和专用适配器，不依据模型名称套用另一供应商的认证。
- 路由决定携带归一化标记，选中后快照到请求上下文和 ChannelMeta。请求转换不重新读取总开关，避免管理操作改变正在执行的请求。
- 显式逐渠道/模型路由继续作为例外；全局新模式使普通聚合渠道不再依赖旧协议覆盖开关才执行默认端点。路由预览和候选筛选使用相同决定。
- 直接适配 New API 的 Messages ↔ Responses 请求转换，复用既有三协议输出处理、身份/Anti-Poison、暂存提交门和账务流程。普通文字、图片、函数工具、并行开关、两轮工具结果和思考意图可转换。
- 有状态的 previous_response_id/conversation/压缩状态、外部签名、未支持的服务端工具或专有字段不伪造、不跨协议默默丢弃。无签名、已向客户端可见的推理摘要可作为 assistant 文本历史保留；不将外国签名当成 Responses 密文。
- 每次上游尝试重置发送计数与 Claude 输出状态；Responses emitter 按尝试编号隔离。提交前切换不复用失败请求的 ID/终态，已提交后继续禁止跨渠道拼流。
- 尝试链记录实际 HTTP 路径与路由来源，不包含认证或 URL 查询参数。分发阶段无候选也写入关联 request ID 的日志；普通用户继续只见公共错误。

## 验证和来源

集成回归覆盖 3 × 3 × 流式/非流式 × 基础/图片思考两种请求的 36 个场景，每个执行两轮工具交互；另有跨协议故障切换、显式零值、工具参数 JSON 和签名边界检查。

New API `6370b2942416` 是主要代码来源；Sub2API `5fc0e486c3f6`、CLIProxyAPI `0f96f568e4db`、Bifrost `dfa57061c467`、LiteLLM `d8c0e2c7153d` 用于专项对照，不导入其整套架构、账号策略、计费或默认预算。具体 dispositions 见 `UPSTREAM_PORTS.md`。
