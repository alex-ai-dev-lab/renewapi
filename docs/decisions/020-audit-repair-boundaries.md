# ADR-020：审计修复的授权、支付与状态边界

状态：Accepted。日期：2026-10-17。适用于本次工作副本，尚未发布。

## 决策

- Session 只提供账户身份，每次面板授权用一次轻量数据库查询读取最新 username/role/status/group；DB 故障拒绝授权。Bearer 复用验证结果，TokenAuth 转发热路径不增加查询。
- Stripe 在既有 TopUp、SubscriptionOrder 嵌入报价与履约字段，通过 `payment-snapshots:v1` 只添加列，不新增报价、名额、事件账本。最小货币单位金额、币种、应发额度、会话和订阅套餐快照决定履约，实付不反推权益。Checkout 使用订单报价和订单号幂等键。
- 成功入账和额度修改同事务。数据库错误向 Stripe 返回 503；重复入账直接确认。已付款但回执/历史权益不完整的订单持久保存 `paid_review` 及原因，再返回成功，等待核实与补偿。旧单缺快照时禁止用当前价格猜权益。
- 待支付和创建结果未知的订阅订单占用限购名额。建单、余额购买、管理员开通和履约统一先锁用户再读取数量；SQLite 真实写入取锁，MySQL/PostgreSQL 行锁。仅已确认终态释放待支付名额。晚到付款重新检查容量，冲突保留审核状态。
- 失败的 Checkout 创建不能证明渠道未建单，保留 `checkout_unknown`。管理员通过 `POST /api/user/topup/stripe/reconcile` 读取渠道真实 Session、核对订单引用、CAS 绑定，并复用相同履约校验；沿用 AdminAuth，记录管理员操作。此接口不创建或退款支付。
- 显式 off 的新请求复用既有 BillingLedger/outbox，首次/追加预扣、结算、退款和任务终态在同一持久事务内调整资金/Token，reconciler 恢复持久化意图及超时孤儿预扣。只由账本写余额，off/shadow 保留兼容统计归属；默认仍为 shadow，不新建账本或切换生产配置。旧 off 无账本差额不自动推算，升级先排空旧在途请求。
- URL/Query/表单各自只拥有已提交筛选、服务端详情、未保存草稿。表格使用业务 ID，页码/筛选/排序/账号变化清选；详情未成功初始化不能保存，后台刷新不得覆盖未保存编辑。
- 非流式上游响应默认最多 64 MiB，可通过 `UPSTREAM_RESPONSE_MAX_MB` 调整；计数以解压后读取字节为准。渠道测试捕获最多 256 KiB，超限判失败。请求处理顺序保持最终规范化、身份注入、BodyStorage，重放与磁盘清理保持原语义。
- 日志 UI 改用双向游标，不做 COUNT/OFFSET；self 保持 ID 排序，admin 保持 created_at/ID 排序，沿用现有复合索引。旧 API 保留 offset ≤ 10000 的结构，两种日志计数均以 10001 哨兵返回 `total_capped`，超限 400 要求游标。总览去除重复渠道聚合，全时段趋势最多 500 桶并覆盖全部日期。
- 游标使用 AES-GCM 隐藏真实 ID 并防篡改，绑定查看者、筛选和页大小；携带初始最大 ID，排除随后插入的日志。它不是授权凭据，每次仍校验当前身份和 self 范围。密钥由 CRYPTO_SECRET（未设置时 SESSION_SECRET）派生，多实例需保持一致；轮换或重启产生不同密钥时旧游标失效，UI 可返回最新日志。URL 保存时间范围和游标，筛选/页大小/查看范围改变重置；旧无游标深页链接从首页重新浏览，不提供任意跳页及精确总数。
- 英文作为随入口加载的 fallback，其他语言按需加载。当前界面继续仅提供简中、英文、日文；旧繁中归简中，其他隐藏语言码仍回退英文。显式切换失败可重试，迟到加载不得覆盖最后选择。

## 产品与运维边界

用户已确认 Midjourney 图片允许公开分享，`/mj/image/:id` 继续匿名读取，不附带 API key；任务查询/提交 API 仍鉴权。R-007 按此产品契约结案，不新增私有或可撤销链接系统。Stripe 的真实测试账户、账单与退款验收仍属于发布前渠道验收；本次只使用签名假事件、故障注入和本地模拟 Stripe 服务。

已有 Stripe `quote_version=0` 旧单先核对渠道收据和历史权益，再通过已有管理员额度/订阅调整补偿并留记录；通用充值补单不得按当前比例自动计算旧 Stripe 权益。新快照订单的管理员强制补单使用固化额度并标记 `manual_override`。`paid_review` 订单持续占名额，处理前不要盲目重建订单或手工释放。
