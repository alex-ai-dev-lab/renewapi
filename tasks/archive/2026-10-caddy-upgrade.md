# Caddy 升级（2026-10-02）

状态：完成。用户要求说明服务器哪一部分版本旧，并在可行时升级。

- 范围：反向代理 Caddy，不升级整个操作系统或应用容器。
- 系统：Ubuntu 24.04.4 LTS；现有 Caddy `2.6.2-6ubuntu0.24.04.3+esm2` 为 Ubuntu 维护包，功能版本缺少 `stream_close_delay`，并非未受维护的系统。
- 已升级至官方稳定版 [`v2.11.6`](https://github.com/caddyserver/caddy/releases/tag/v2.11.6)（2026-10-01 发布）。检查发布说明、包来源、配置兼容与五个站点后安装。
- 现有 Caddy 仅标准模块。配置、证书、其他站点上游和应用数据保留；升级二进制需受控重启，先备份回退包并等待活动连接排空。
- 使用服务器现有代理下载；完成后检查真实运行进程版本、各站点响应、RenewAPI 页面与接口，并验证流连接在配置重载时得到保护。

## 安装与配置

- 通过服务器代理下载官方 amd64 Debian 包；GitHub asset SHA256 与发布清单 SHA512 均校验通过。旧 Ubuntu ESM 安装包及旧程序完整保留。
- 配置官方稳定 APT 源 `https://dl.cloudsmith.io/public/caddy/stable/deb/debian`，使用专用 signed-by 密钥；主密钥指纹 `65760C51EDEA2017CEA2CA15155B6D79CA56EA34`。仅为 Caddy 设置官方源优先级 700，避免旧 Ubuntu ESM 优先级阻挡后续官方版本更新；没有更新其他系统软件。
- 先安装包并抑制包脚本的提前重启，确认旧进程仍在服务。临时 `policy-rc.d` 已移除。
- 现有配置转换到新版支持的 `basic_auth` 名称，保留认证账户、证书路径、站点上游及旧静态资源服务。
- 保留旧版 1MiB 请求头上限，避免新版默认 16KiB 限制改变既有调用。其余采用新版默认安全行为。
- RenewAPI 的两条反代启用 `stream_close_delay 5m`，全局 `grace_period 5m`。systemd 关闭宽限设为 330 秒，保留原 `CAP_NET_BIND_SERVICE` 权限和进程数限制。

## 验证与切换

- 用新二进制在独立本机端口运行五站点副本，未接管生产监听端口。9 个 URL 的状态与生产基线一致，包含 API 未授权和文档管理入口鉴权。
- 临时本机模拟上游验证 SSE 逐帧输出；事件到达约为 0.001、0.202、0.402 秒。
- 建立真实 WebSocket，在变更并重载测试配置后仍能收发消息，确认流连接重载保护有效；临时监听器和进程已关闭。
- 确认现有上游连接为 0 后执行受控重启，耗时 0.259 秒。49 次连续公网探测零失败，最大采样耗时 1936.13ms。
- 实际运行 PID 从 1763 变为 1166576；读取 `/proc/<PID>/exe version` 确认新进程为 2.11.6，而不只检查磁盘上的程序。
- `caddy.service` active/running，服务用户配置校验通过；APT installed/candidate 均为 2.11.6，运行配置包含 300 秒流连接保护。
- RenewAPI 容器 ID 和启动时间未改变，仍为 `v1.0.0`。桌面/手机首页、登录页、价格页共 6 项浏览器检查通过，零页面、控制台及 HTTP 错误；未截图。
